# Fablewick v2 app

React 19 + TypeScript + Vite + react-router. Built to `dist/` and shipped
under `/fablewick/`, alongside the existing `library/` (which stays for
old links). Scaffolded in wave 1a of `docs/v2-plan-2026-09-04.md`.

## Commands

```sh
npm install       # once
npm run sync      # regenerate src/data/*.json and public/art/ from the repo's sources
npm run dev       # local dev at :5173, served under /fablewick/ (sync runs first)
npm run build     # sync + typecheck + production build to dist/
npm run preview   # preview the production build
python verify.py  # build + Playwright checks (routes, fonts, console, no h-scroll) + screenshots
python shots.py   # build + screenshot every route at 1440x900 and 390x844, no checks
```

`npm run sync` and `npm run build` both run `scripts/sync-data.mjs`
first — nothing in `src/data/` or `public/art/` is meant to be hand
edited, since the next sync overwrites it.

## Where the data comes from

Nothing here is retyped by hand. `scripts/sync-data.mjs` reads, at build
time:

| what | source | written to |
|---|---|---|
| Fablewick book meta (title, ageRange, themes, lesson, summary) | `../src/content/books/<slug>/meta.json` | `src/data/fablewick.json` |
| Fablewick story text, 5 languages, plus every UI string (nav labels, page label, end mark) | `../library/reader-<slug>.i18n.json` | `src/data/fablewick.json` |
| Fablewick art | `../src/assets/pages/<slug>/{cover,page-NN}.jpg` | `public/art/<slug>/` |
| Ramkabir book data (title, moral, scenes, three levels: kids/adults/seniors) | the `const BOOKS = [...]` literal inside `../library/ramkabir-fablewick.html`, parsed with `JSON.parse` after slicing it out of the script tag, never `eval`'d | `src/data/ramkabir.json` |
| Ramkabir art | `../library/assets/ramkabir/<slug>/{cover,page-N}.jpg` | `public/art/heritage/<slug>/` |
| Headshot (About section) | `claude-workspace/1-Projects/mann-landing-v3/public/headshot.jpg` | `public/headshot.jpg` |

Every count anything in the app reports (book count, page count per
language, language count) is measured from these files at sync time —
none of it is a typed-in number. `src/data/index.ts` has the typed
loaders (`fablewickBooks`, `ramkabirBooks`, `getFablewickBook`,
`getRamkabirBook`, `fablewickLanguages`, `ramkabirLanguages`).

`sync-data.mjs` also prunes any `public/art/<slug>/` folder whose slug is
no longer live in the source data, so a removed book's old images don't
keep shipping.

`public/.gitignore` keeps `art/` and `headshot.jpg` out of git — they're
copies of files that already live elsewhere in the repo, regenerated by
`npm run sync`. `src/data/fablewick.json` and `src/data/ramkabir.json`
are gitignored for the same reason.

## Structure

- `src/styles/tokens.css` — the Fablewick palette (cream/ink/sage/amber/coral),
  the dusk gradient (stops read verbatim from `library/fablewick-landing.html`'s
  reader stage), radii (12/20/28) and a three-step shadow scale.
- `src/components/` — `Button` (filled/outline/ghost, 44px min height,
  focus ring), `Section`, `Reveal` (fade-up on scroll via
  IntersectionObserver, no-op under reduced motion), `Header` (mark, nav,
  language chip row).
- `src/pages/` — one placeholder per route: `Library` (`/`), `Reader`
  (`/read/:slug`), `Heritage` (`/heritage`), `HeritageReader`
  (`/heritage/read/:slug`). Each names its route and lists what the data
  loaders actually found, so waves 2 to 4 have real data to build the
  real page against.

## Known scaffold limits

- The production JS bundle is ~740 kB (202 kB gzipped) because every
  book's full text across all 5 languages is bundled inline via the
  static JSON import. A later wave should code-split per-book text
  (dynamic `import()` per slug) once the reader is real, rather than
  shipping every story's text on every route.
- No favicon yet — the stock Vite one was removed and nothing replaced
  it (no new image generation per the plan's fence). A later wave should
  add one from existing art.
- `verify.py` and `shots.py` add an SPA fallback (serve `index.html` for
  any path that isn't a real file) so a direct navigation to a client
  route resolves locally. GitHub Pages does not do this automatically;
  the "ship" wave in the plan needs its own 404.html rewrite (the usual
  SPA-on-Pages trick) for deep links to survive a real page load.
